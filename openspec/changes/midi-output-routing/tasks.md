## Phase 4: MidiOutputSink (JUCE-aware — device lifecycle, dispatch, timestamp anchor, panic guard; manual-gate-only)

- [ ] 4.1 No RED/GREEN split possible (`juce_audio_devices`, same constraint as Phase 3). Write `Source/midi/MidiOutputSink.h/.cpp` directly, per design's exact interface and the six Architecture Decisions it embodies:
  - ctor `explicit MidiOutputSink (int outputChannel) noexcept;` (channel clamped `[1,16]`); dtor calls `closeDevice()`.
  - message-thread-only: `bool openFirstAvailableDevice();` (`getAvailableDevices()[0].identifier` -> `openDevice` + `startBackgroundThread()`; `false` = none available / open failed — the valid degraded state, not an error); `bool isDeviceOpen() const noexcept;`; `juce::String getOpenDeviceName() const;` (never called from the callback).
  - `void closeDevice() noexcept;` — implement Decision 4's EXACT four-step order, each its own checked sub-step: (a) `device->clearAllPendingMessages()`; (b) `device->sendMessageNow (...)` with the CC 123 message packed via `makeAllNotesOff (channel)`; (c) `device->stopBackgroundThread()`; (d) `device.reset()`. Idempotent when already closed (early-return if `device == nullptr`). **Verify at apply**: confirm `juce::MidiOutput::clearAllPendingMessages()` exists in the pinned JUCE version; if absent, substitute the order to `stopBackgroundThread()` -> `sendMessageNow (CC123)` and record the substitution here per design's Open Questions.
  - `void prepare (double sampleRateToUse) noexcept;` — Decision 5: sets `sampleRate`, zeroes `elapsedSamples`, captures `startMs = juce::Time::getMillisecondCounterHiRes()` ONCE per call (not per block).
  - `void dispatch (const juce::MidiBuffer& buffer, int numSamples) noexcept;` — Decision 6 + the exact ordering contract: if `device != nullptr && sampleRate > 0.0 && ! buffer.isEmpty()`, call `device->sendBlockOfMessages (buffer, startMs + elapsedSamples * 1000.0 / sampleRate, sampleRate)`; then `elapsedSamples += numSamples` UNCONDITIONALLY (even with no device, even on an empty buffer) — this ordering (guarded send, unconditional counter advance) is load-bearing; implement it exactly as shown, not as an early return that skips the counter update.
  - `void sendImmediately (const juce::MidiBuffer& buffer) noexcept;` — `sendMessageNow` per message, used only from `releaseResources`'s shutdown path, never the callback.
  - private members exactly: `std::unique_ptr<juce::MidiOutput> device; const int channel; double sampleRate { 0.0 }; double startMs { 0.0 }; long long elapsedSamples { 0 };`
